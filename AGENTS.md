# Working agreement

- Build FairGate in small learning phases.
- Before coding, state the current phase and its intended outcome.
- Implement only the agreed phase, verify it, and explain the changed files.
- Keep a phase guide with a request walkthrough, relevant commands, and a small exercise.
- Stop at the learning checkpoint. Do not start the next phase until the user says they understand and are ready.
- The user reviews, stages, and commits the changes themselves. Do not create commits, push, or stage files unless they explicitly change that instruction.
- Keep changes small enough for the user to explain and modify during an interview.
- Prefer simple implementations and introduce infrastructure when the current phase needs it.
